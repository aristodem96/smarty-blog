# AI usage

Tool: Claude Code (Claude Opus 5.5 model).
Principle: the author makes architectural decisions; the AI proposes options and does routine work
once the approach is agreed. The author reviews and commits every stage personally.

| Stage | What the AI did | What the author decided / did |
|-------|-----------------|-------------------------------|
| 0 | Wrote `.gitignore` with explained rule groups. Generated the documentation skeleton (`CLAUDE.md`, `docs/*`), `.claude/settings.json` and custom commands to the author's specification. Prepared two structure options and a draft DB schema. | Defined the working rules, stage plan, quality criteria and documentation set. Chose the layered-by-type structure (ADR-002), slugs in URLs instead of ids, and `description` as TEXT instead of the VARCHAR(500) proposed by the AI (ADR-003). |
| 1 | Proposed stack and version options; wrote the `Dockerfile`, `entrypoint.sh`, Nginx config, `docker-compose.yml`, `composer.json` and a smoke test; verified startup, Nginx routing and restart idempotency. | Chose Nginx + PHP-FPM, Composer in the container and entrypoint-based initialization (instead of the Makefile the AI recommended). Questioned the AI's suggestion of a newer PHP → compromise: 8.1 minimum in composer.json, 8.3 in Docker. |
| 2 | Proposed migration mechanisms; wrote the SQL migrations, `bin/migrate.php`, `Database` and config; spotted the `updated_at ON UPDATE` conflict with the view counter; verified idempotency and `--fresh`. | Chose numbered migrations with a `migrations` table, `--fresh` without down migrations, moving the DB connection into stage 2, and switching to `utf8mb4_0900_ai_ci`. |
| 3 | Proposed options for the router, response format, DI, request object and layout; wrote the Core classes, stub controllers, templates and bootstrap; verified routes, 404/500, HEAD/POST and auto-escaping. | Chose a `Response` object instead of the AI's recommendation of returning strings (anticipating growth), a router class, manual dependency wiring and a `Request` object. |
| 4 | Proposed options for the data source, transliteration, images and seeder behavior; wrote `BlogSeeder`, `Slugger`, `bin/seed.php` and the Ukrainian content templates; generated 8 SVGs with a one-off script (not in the repository); found and fixed a transliteration bug after apostrophes; verified determinism and `--if-empty`. | Chose an own generator over Faker, Ukrainian transliteration over `ext-intl` or English content, committed SVGs, always-recreate seeding plus `--if-empty`, and a seeder class with its own namespace. |
| 5 | Proposed three query strategies (ROW_NUMBER / N+1 / LATERAL), the data format and category order; wrote entities, repository, controller and templates; optimized the subquery (ranking ids only); cross-checked results against naive per-category queries, checked EXPLAIN and an empty database. | Chose a single `ROW_NUMBER()` query, readonly entities over arrays, and ordering categories by their latest article. |
| 6 | Proposed options for the sort format, page size, invalid page handling, total count and pagination style; wrote the enum, `Pagination`, repository, controller and templates; verified status codes, ordering across all pages, the window on 300 articles and EXPLAIN. | Chose enum sorting with a fixed direction, 9 per page, 404 for non-existent pages, a separate COUNT, and windowed pagination (instead of the full page list the AI recommended). |
| 7 | Proposed options for view counting, the tie-breaker and handling too few similar articles; wrote `ViewedArticles`, repository methods, controller and template, extended `Request`/`Response`; verified the counter (refresh, HEAD, new browser, forged cookies) and cross-checked similar articles for all 80 articles. | Chose cookie deduplication, "newest first" among equals, and showing only the similar articles found. |
| 8 | Proposed options for the SCSS build, structure and theming; wrote the SCSS (variables, mixins, theme, components), the `assets` service and cache busting; verified the layout with headless Chrome screenshots at 3 widths in both themes and fixed pagination wrapping on phones. | Chose a dedicated compose build service, a simplified one-file-per-BEM-block structure, and a light + automatic dark theme (instead of the light-only theme the AI recommended). |
| 9 | Translated the documentation into English. Reviewed the whole project (security, task compliance, readability) and listed 10 findings with priorities; after approval implemented them (production `php.ini`, Nginx headers and caching, lazy DB connection, `APP_ENV`, heading outline, meta descriptions, MIT license) and verified each one, including behavior with MySQL stopped. | Required all repository files to be in professional English; chose to keep `CLAUDE.md`, `.claude/` and `docs/` public for transparency; decided to fix every review finding, including those the AI suggested leaving as documented limitations. |
| 9 | Translated the site UI and the seeder content into English (categories, topics, title/paragraph templates, error pages, sort labels, date format), reseeded and verified every page. | Decided to make the whole site English, not only the articles. |
